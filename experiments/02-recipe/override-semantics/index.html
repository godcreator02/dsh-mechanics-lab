02-recipe / override-semantics

同一个 id 再写一次，改的是哪条已经在树里的条目

裸 - id:（不带 insert）不新增条目，是把 overrides 里写出的每一个键原样盖到那条已存在的条目上——整键替换，不是深度合并；overrides 没提的键，原样留着。

档次 ① 📗 复述型 🔬 含 4 条边界实测 ✅ 满覆盖 · 6 条用例 不需要 web

这一项讲的是什么

配方（recipe，见 00-base/minimal-profile）由多层 patch 叠成，层与层之间「后叠的赢」（层叠规则见 02-recipe/layer-stack）。每一层是一个 YAML 数组，数组里的每一项要么带 insert——往组合树里插一条新 条目（entry：配方里的一行，写着挂哪个插件、给它什么配置；insert 的完整语义见 02-recipe/insert-semantics）， 要么不带 insert、只写一个裸的 id——指向一条已经在树里的条目，去改它。这一项讲的正是后一种写法：覆盖。 同一个 id 在后面某一层再出现一次，框架不会造出第二条同名条目，而是把这一项当成对那条已存在条目的一次修改指令—— 它怎么改、改哪些键、改不到会怎样，是这一项要讲清楚的全部内容。

机制怎么工作

唯一实现是 cordis-plugin-include 的 applyEntryPatches() （<npx 缓存>/node_modules/@deepseek-ai/cordis-plugin-include/src/index.ts:58-128）——insert 分支和覆盖 分支住在同一个函数里，靠这一项有没有带 insert 岔开。走一遍覆盖分支实际做的五件事。

静态：三个只用 --dump-config 判定的边界

null / 找不到 id / 野字段这三条不用拉真实例——--dump-config 的 renderConfigDump() 和运行时挂载走的是同一个 applyEntryPatches() 调用，dump 算出来的树就是真会被拿去挂载的那棵树。dump 成功时 会静默丢掉 stderr（覆盖的警告恰恰走 stderr），三个 profile 都额外抓了一遍 stderr 判定。

动态：改的是已经挂上的那条条目，不是造一条新的

三个 profile 都先用 - insert: 挂上同一个教学插件 speaker（fixtures/speaker.mjs）， 写两个 config 键：台词 和 音量。speaker 拿到 config 就把它原样报给 lab-recorder 采集器 （labObserver 机制见 00-base/recorder-reach）——判定全靠它报出来的内容，不靠猜。三个 profile 各自在后面 再写一条裸 id，覆盖的东西各不相同。

读出来的是什么

①

覆盖替换的是 target 整个键值，不是深合并。同一个 config 键，旧值写了两个键，覆盖只重述一个，另一个就没了—— 覆盖传的是整个新 config 对象，替换了旧的整个 config 值，不是把新键并进旧的里面。 test_bare_id_changes_the_entry_that_is_already_there

②

null 是字面赋值，不是删除。键还在，值变成了字面 None——覆盖这行代码走的是纯赋值，不会因为 value 是 null 就把键删掉。 test_null_sets_key_to_null_not_delete

③

覆盖找不到 id：只警告、跳过这一条，同批其余 patch 照常生效。运行时也不会凭空造出一个新条目， 而且日志里一个字都没有——排查时不能指望日志会提示。 test_missing_id_warns_and_skips_rest_still_applies · test_changing_an_id_that_is_not_there

④

覆盖分支没有字段白名单，野字段原样带着走，不报任何错误或警告。它不是非法，只是没人读。 test_arbitrary_fields_pass_through_patch

⑤

disabled 也能被后面一条覆盖关掉，不用回去改前面那条。前面那行原样留着，关不关由后面这条说了算。 test_bare_id_can_switch_disabled_on

/**
 * 把自己收到的 config 原样报给 lab-recorder。
 *
 * 判定全落在它报出来的内容上——改没改成，问它本人最准。
 */

export const inject = ["labObserver"];

export function apply(ctx, config) {
  const say = ctx.labObserver.for(ctx);

  say("我收到的 config", { 内容: config ?? null });
}
