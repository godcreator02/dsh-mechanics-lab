四层怎么叠出生效配置

同一个 id 在四层各写一次，后叠的赢——外加一层官方文档没写的第五层。

档次 ① 📗 复述型 ✅ 8 条用例 不需要 web

id 叫 shared，四层各写一次

bundle profile home overlay 内置（待验）

四层各自的来源也认得出来：bundle 层来源＝包名，profile／home／overlay 三层来源＝各自那份 cordis.patch.yml（或 --patch 指的文件）的绝对路径—— test_four_layers_identifiable 已验。

①

home 层文件不存在＝没有这层，照常启动；内容非法（顶层不是数组）当场报错。 报错文本钉死在源码 JSDoc 里，不是文档正文。 test_home_layer_missing_equals_no_layer · test_home_layer_illegal_content_fails_loud

②

--patch 给多个时也按「后来者赢」——argv 顺序，后写的顶掉先写的。 跟前四层是同一条规则，只是发生在第四层内部。 test_overlay_order_by_argv

③

home 层不属于任何一个 profile：写一次，这个 home 下每个 profile 都吃到； 跟 profile 层各写各的也不冲突，两条并存、各收各的 config。 test_the_other_place_works_the_same · test_the_home_place_hits_every_profile · test_two_places_two_entries

⚠

「四层」是文档层面的说法，源码层面实际是五层。第五层不受任何 patch 文件控制， 只受「组合树里有没有对应 id」和环境变量驱动，压过前四层——但本项零用例覆盖它，图里画成 虚线正是为了不让它看起来跟前四层一样确凿。

判定与证据出处在 test_layer_stack.py 的模块 docstring，此页只负责让你看懂。
