05-reload / watch-root

hmr 主 watcher 的 root 语义

代码热重载靠一个盯着目录树的 watcher——这一项讲的是这棵树由谁划定、划的范围怎么解析，以及一次改动落进树里之后，那一瞬间发生了什么。

档次 ① 🔬 发现型 ✅ 满覆盖 · 9 条用例 不需要 web

这一项讲的是什么

条目（entry，配方里的一行，见 00-base/minimal-profile）挂载之后，运行时对应一个 fiber——这个插件这一次生命的载体，滑过 PENDING → LOADING → ACTIVE → UNLOADING → DISPOSED 这几个状态（完整定义同见 00-base/minimal-profile）。给一条条目挂 @deepseek-ai/cordis-plugin-hmr（provide 一个叫 hmr 的服务，包级声明依赖 timer，是同一份硬依赖，见 00-base/minimal-profile），这套插件系统就多了一件事：运行中改代码不用重启进程。干这活的是 hmr 里的一个「主 watcher」——它盯着若干目录树，一旦树里有文件变了，就把对应插件的 fiber 拆了重建，条目本身的 id 不变。

这一项要讲清楚的是两件事：这棵目录树由谁划定——root 这一份配置——以及一次改动落进树里之后，旧的什么时候真正拆完、新的什么时候真正开始、两者中间有没有重叠。

机制怎么工作

走一遍一处代码改动要经过的几步：①②是 root 怎么变成 watcher 真正盯着的目录，③④是改动发生之后 watcher 怎么判定要不要处理，⑤是判定要处理之后，条目状态怎么变。

改一行代码，那一瞬间

毫秒数取自真实归档。横轴按事件顺序等距摊开，不按时间比例—— 段内几个事件只差零点几毫秒，按比例画会挤成一团。这是 rooted profile（root: ['.']，代码在 profile 目录里，侧栏可点开）一次真实运行的记录：启动、静置 1.3 秒、改一行代码。

PENDING LOADING ACTIVE UNLOADING DISPOSED 说话

两条读法：说话在 ACTIVE 之前——apply 跑在「加载中」，不是「加载完」，插件在自己的 apply 里看不到自己是 ACTIVE（2.2ms 说话／2.7ms 才 ACTIVE）。「拆干净再建」是错觉——旧的进 UNLOADING 之后、真正 DISPOSED 之前，新的已经开始 LOADING 了；hmr 报「重新加载了」时旧的还活着（1322.1 UNLOADING → 1322.6 新的 LOADING → 1322.8 hmr 报重载 → 1322.9 旧的才 DISPOSED）。

root 填什么，热还是冷

同一份观测手段——读事件流里插件上报的「版本」变没变——套在九种配置组合上。「代码落在哪」和「root 填什么」各自独立变化，热或冷由两者共同决定。

不写（默认值 ['.']）profile 目录里，单文件 热test_no_config_means_the_default_root

同一个包（hmr-linked），只把 root 从 ['.'] 扩到源码真实路径，结果从冷翻成热——这是表里唯一一对「代码落点不变、只改 root」的对照。它冷的原因是 profile 目录通往 junction 那头代码的唯一路径要穿过 node_modules，那正是 hmr 默认 ignored 名单第一项；完整证据链（picomatch 怎么判、chokidar 报的路径为什么和 loader 记的对不上）在 05-reload/ignore-rules。

读出来的是什么

①

root 不写时默认值是 ['.']（相对 base 解析，base 不写时是 ctx.baseUrl），即 profile 目录本身——第一份最小实例因此「其实早就能热重载」，只是没写明。 test_no_config_means_the_default_root

②

'.' 与 profile 目录的绝对路径等价。两种写法算出来的是同一个 watch base。 test_absolute_root_works_too

③

代码摆在 profile 目录里，一定热——不管是单文件还是整份包物理拷贝进去。这是本项全部结论的对照组：同一个包、同一种改法，只要代码不经 junction，就该重载。 test_root_dot_reloads_the_plugin · test_inline_package_reloads

④

root 指向别处或写成空数组，改代码没有任何反应——这不是「hmr 坏了」，是它确实只盯配置里列出的那些目录。 test_root_pointing_elsewhere_notices_nothing · test_empty_root_watches_nothing

⑤

经 junction 装进来的包，默认 root: ['.'] 够不着它。profile 目录下通往链接那头代码的唯一路径要穿过 node_modules——hmr 默认 ignored 名单第一项就是 **/node_modules。 test_linked_package_default_root_notices_nothing

⑥

条目从哪一层来（活层手写 / bundle 自注册）不影响能不能被热重载。把 root 扩到源码真实路径、去掉 ignored 里的 **/.*（详见 ignore-rules 项），条目由包自己那份 patch 生，照样重载。 test_bundle_self_registered_entry

⑦

root: [] 只关掉代码这一条路，不是「什么都不监听」。关掉之后跑着的代码永远拿不到新实现——ESM 在 import 那一刻就把静态依赖图读盘编译完了，调用不会回头读磁盘；每 700ms 一次的心跳排除了「压根没人调用」这种会跟「拿到旧值」混淆的解释。 test_with_hmr_off_the_running_code_never_notices

⑧

说话在 ACTIVE 之前。apply 跑在「加载中」，不是「加载完」——插件在自己的 apply 里看不到自己是 ACTIVE。 test_root_dot_reloads_the_plugin（时间线：2.2ms 说话 ／ 2.7ms 才 ACTIVE）

⑨

「拆干净再建」是错觉。旧的进 UNLOADING 之后、真正 DISPOSED 之前，新的已经开始 LOADING 了；hmr 报「重新加载了」时旧的还活着。 test_root_dot_reloads_the_plugin（时间线：1322.1 UNLOADING → 1322.6 新的 LOADING → 1322.9 旧的 DISPOSED）

  const say = ctx.labObserver.for(ctx);
