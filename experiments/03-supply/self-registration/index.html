03-supply / self-registration

一个包怎么把自己挂上树

一个真正被人安装、分发出去的插件包，不想指望"装它的人替它手写一条 insert"——它想自己带着"该往树上插什么"这份说明，装上就生效。这一项讲的是这条供给路径要满足的两个条件，以及少一个会怎样。

档次 ① 🔬 发现型 ✅ 满覆盖 · 2 条用例 不需要 web

这一项讲的是什么

一个 profile 只需要两个文件就能起来——package.json 里的 bundles 名单，加上 cordis.patch.yml 那份活层（见 00-base/minimal-profile）。活层是人日常动的那一层：想让某条目上树，最直接的写法是在这里手写一条 insert（见 02-recipe/insert-semantics）。但一个真正被打包、分发出去的插件，不太可能指望每个装它的人都替它写这一条——它想做到"装上就自动生效"。03-supply 这一组回答的问题是"插件从哪来"；这一项讲的是其中一条供给路径：包自己声明一份属于自己的 patch，只要它被这个 profile 认下，那份 patch 里写的条目就自动出现在组合树上，活层不用改一个字。这条路径叫包自注册（self-registration）。

机制怎么工作

走一遍一个包怎么把自己焊上树：①②是包与 profile 各自要做的一件事，③是启动时框架怎么把它们对上号，④是少一样时会发生什么。

两个教学插件，一正一负

两条用例各用一个只声明 dsh.bundle、不声明别的教学插件（ch2-greeter 与 ch2-courier），避免混进无关变量。判据落在 lab-recorder 这个观测插件（00-base/recorder-reach 讲过它怎么采集）上报的内容上：条目在不在树上、说过什么话。ch2-greeter 那份包先被拷进 $DSH_HOME/pkg/ 再 link 进 profile（侧栏可查看这份运行时拷贝，跟仓库里的源文件逐字节相同）——保证这次实验不会碰到仓库里那份源文件；ch2-courier 没有这一步，直接从 fixtures/ link 过去。

看到的：一个上树，一个什么都没发生

selfmount · ch2-greeter✓ 条目自动上树
活层（cordis.patch.yml）只写了 timer / hmr / lab-recorder 三条，一个字没提 greeter
dsh.profile.bundles = ['ch2-greeter']
组合树上多出的条目：greeter（1.03s）
它说的话：['第一版']——包自己那份 patch 里写的 config.版本 原样送达
notinstalled · ch2-courier✗ 什么都没发生
同一个包目录，同样 link 进了 node_modules，只是没被列进名单
dsh.profile.bundles = []
组合树上的条目：['hmr', 'include', 'lab-recorder', 'timer']（25.16s，含 10 秒固定等待）
它说的话：（一句都没有）——包里那份 cordis.patch.yml 没人读过

两条用例除了"包名有没有写进 dsh.profile.bundles"之外一模一样：同样的目录结构、同样建好 node_modules junction、同样起一个实例。唯一变量就是这一份名单。

读出来的是什么

①

包自注册需要两个条件同时成立：包声明 dsh.bundle.patch，且包名进了 dsh.profile.bundles 名单。两样齐备时，profile 活层一个字不用写，包自己那份 patch 里的条目就会出现在树上、apply 会跑、config 会送达。 test_a_package_mounts_itself

②

缺一样，什么都不会发生——不是报错，是安安静静地不存在。同一个包、同样建好 node_modules junction，只要没被列进 dsh.profile.bundles、活层也没手写 insert，条目就不存在：包目录里那份 cordis.patch.yml 没人会去读它。 test_the_package_alone_registers_nothing

/**
 * ch2-greeter ——一个包身兼两职：
 *
 *   1. 它是**包**：`package.json` 声明了 `dsh.bundle.patch`，指向同目录的
 *      `cordis.patch.yml`。这个包一旦进了某个 profile 的 bundle 名单，那份
 *      patch 文件里写的条目就自动上树——不用手写 insert。
 *   2. 它也是那份 patch 文件指向的**插件模块**：`name: ch2-greeter` 找的就是
 *      这个文件，真正的 `apply` 长在这儿。
 *
 * 只干一件事：把自己收到的 `版本` 报出来。
 */

export const inject = ["labObserver"];

export function apply(ctx, config) {
  const say = ctx.labObserver.for(ctx);

  say("我跑起来了", { 版本: config?.版本 ?? null });
}
