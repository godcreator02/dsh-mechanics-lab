config 原样送达 apply

patch 里 insert 一条条目时写的 config，键名、值、深度全部原样递到 apply(ctx, config) 的第二个参数——没写、拼错键名，都安静地变成同一个 undefined。

档次 ① 📗 复述型 ✅ 4 条用例（2 参数化） 不需要 web

这一项讲的是什么

插件模块导出的 apply(ctx, config) 函数，第二个参数 config 从哪来——这一项讲的就是这条最短的通道：从 patch 里 insert 一条条目时写的 config:，到这条条目被激活时 apply 真正收到的那个值，中间发生了什么、又有哪些地方什么都没发生。 每条条目（entry，配方里的一行）一共有六个字段——id、name、 config、disabled、group、inject， 定义在 cordis-plugin-loader 的 config/entry.ts 里；这一项 只钻其中一个，config，按它自己的定位，就是「传给 apply(ctx, config) 的第二个参数」。

机制怎么工作

这条链条只有三步，中间没有能单独拍照的状态，摊开讲比做成 分步舞台更诚实。

patch 里的 config: 跟 id / name 写在同一条 insert 里， 可以是任意深度的对象、数组、标量，或者 null。
→
entry.options.config loader 把这段 YAML 解析成对应的 JS 值，原样挂在这条条目的六个字段之一上—— 不套 schema，也不检查形状。
→
apply(ctx, config) 这条条目被激活、插件模块的 apply 函数被调用时， entry.options.config 原样作为第二个参数传入。
第一步没发生会怎样： insert 里压根没写 config:， 或者键名拼错（比如 cofnig:）——两种情况下 entry.options 上都没有 config 这个字段，第三步收到的就是 JavaScript 的 undefined。没有报错，也没有警告。

四种 config，插件收到什么

下面四种都是真跑过的 profile：各自的活层（cordis.patch.yml） 只挂了一条教学插件 config-echo——它在 apply() 里把收到的 第二个参数原样写成 JSON，落在 process.cwd() 下的 received-config.json（实现见右边侧栏 fixtures/config-echo/index.js）。 左边是写进 patch 的 YAML，右边是这条插件真正收到、又在用例里打印出来的内容。

①

写什么就收到什么，中文键也一样。 键名、值、类型一个不差地原样送达； loader 不做类型转换、不做过滤。 test_config_reaches_apply_unchanged

②

结构深度不受限。 三层深字典、数组里套字典（元素本身还是复杂结构）、 null、浮点，全部原样送达；config 的结构不受 loader 的任何约束，约束（如果有）只能来自插件自己声明的 schema。 test_nested_shapes_survive

③

没写 config、和把键名拼错——结果完全一样。 插件照常跑起来，第二个参数是 undefined，全程没有任何报错或警告；写插件时 config 要当成「可能没有」来接：config?.xxx ?? 默认值。 test_missing_or_mistyped_config_is_undefined[absent] · [typo]

判定与证据出处在 test_config_delivery.py 的模块 docstring，此页只负责让你看懂。

/**
 * config-delivery 用的教学插件：把 apply() 收到的第二个参数原样报出来。
 *
 * 输出落在 `process.cwd()`（dsh 子进程的 cwd 就是 profile 目录，各 profile
 * 互不相同），**不从 config 里读落点**——这样连「一个 config 都不写」的场合
 * 也能看到结果。`received: typeof config` 单独记一笔类型，是因为 `undefined`
 * 放进 JSON 会让整个键消失，不这样区分就分不清「收到了 undefined」和
 * 「插件根本没写这个键」。
 */

import { writeFileSync } from "node:fs";
import { join } from "node:path";

const MARKER = "config-delivery-v1";
const OUTPUT = join(process.cwd(), "received-config.json");

export function apply(ctx, config) {
  writeFileSync(
    OUTPUT,
    JSON.stringify({ marker: MARKER, received: typeof config, config: config ?? null }, null, 2),
    "utf8",
  );
}
