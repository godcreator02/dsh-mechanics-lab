01-entry / apply-runs

怎么从外部证明 apply 真的执行了

配方里写了一条插件，证明不了它真的跑过——这一项拿一份进程外部也验证得了的证据， 把「进树」和「被执行」这两件事分开钉死。

档次 ① 🔬 发现型 ✅ 2 条用例 不需要 web

这一项讲的是什么

活层（user patch layer）里写一条 insert，只是把一行描述放进了配方。 --dump-config 能看到这条条目、看到它的 name 和 config， 但那只证明「配方里有这一行」——证明不了插件真的被跑过：模块有没有被 import、 apply(ctx, config) 有没有被调用，静态 dump 都看不见。

这一项拿一样从进程外部也验证得了的证据把后者钉死——见证文件（witness）： 教学插件在 apply() 里主动写出的一个 JSON 文件，把「我被执行了」这件事和执行时刻 一起记下来。同时验一条反过来的对照：插件文件已经摆在 node_modules 里，只是活层 没写那条 insert，它会不会自己被捡起来。

机制怎么工作

从活层写下一行 insert，到进程里跑出一份能验证的证据，中间是四步；右边文件窗能点开 每一份源码，这里只把顺序理清。

  1. 活层写 insert。本项唯一新增的一条：id: lab-minimal， config.witness 指到一个文件路径。insert（不带 id）是往根列表末尾 追加一条——新增插件的唯一姿势；裸 id: 是「改已有条目」语义，目标不存在时只 警告并跳过，插件永远不会被加载。
  2. loader 挂载条目、import 模块。条目的 name 被解析到 fixtures/lab-minimal/index.js，Node 把这个模块的顶层代码求值一次—— moduleLoadedAt 这个 const 就在这一刻被赋值，此后不会再变， 除非模块被重新 import。
  3. 框架调用 apply(ctx, config)。这才是插件真正「运行」的时刻：函数体里 再取一次时间戳记成 appliedAt，跟 moduleLoadedAt、marker、 原样透传的 config 拼成一个对象。
  4. 见证文件落盘。writeFileSync 把这个对象写到 config.witness 指的路径——这份文件此后就是「apply 被执行过」的外部证据，不用碰 ctx， 看文件就够。

为什么两个时刻要分开记。右边 index.js 里能看到， moduleLoadedAt 写在模块顶层，只有这个模块被（重新）import 才会重新赋值； appliedAt 写在 apply 函数体内，这个条目每被激活一次就重新赋值一次， 跟模块是不是新 import 的无关。这是两个字段各自的写入时机直接推出的结果，不是另外测出来的—— 下面这张表把三种情形摊开：

appliedAt不变变变

反过来——插件在磁盘上，活层没提它。lab-minimal 照样被 link 进了 profile 的 node_modules（见右边 unmounted/package.json），但活层里没有那条 insert。loader 只认活层 写了什么，不会去扫 node_modules 里有什么——挂载的判据是「配方里有没有这一行」， 不是「文件在不在硬盘上」。

两条用例分别落在 run 和 unmounted 两个 profile 上—— 同一份 lab-minimal、同一份基线，唯一的差别是活层写没写那条 insert。

这一次观测里 moduleLoadedAt 和 appliedAt 完全相同 （都是 07:10:39.157Z）——这正是预期结果：boot 阶段这个条目只被处理了一次，import 和 apply 前后脚发生，两个时刻本来就不会拉开肉眼可见的差距。上面那张表说的是两者各自什么时候会 重新赋值，不是「两者总会不一样」。

/**
 * apply-runs 用的教学插件：一个 DSH 插件最少长什么样，全部家当就三样——
 * package.json 的 "type": "module"、exports["."] 指向本文件、导出一个
 * apply 函数。不 inject 任何服务、不注册路由、不碰 UI，这样「插件被
 * 加载了」这件事就没有任何别的解释。
 *
 * 观测手段是写一个见证文件，而不是打日志：日志可能被吞、被缓冲、被格式
 * 变化骗过去；文件存在与否是硬事实。
 */

import { writeFileSync } from "node:fs";

/** 代码版本指纹。改了这个值就能证明跑的是新代码。 */
const MARKER = "apply-runs-v1";

/** 模块顶层求值：模块被 import 的时刻。它变了说明模块被重新 import 过。 */
const moduleLoadedAt = new Date().toISOString();

/**
 * @param {object} ctx    插件上下文（本项不用它）
 * @param {object} config 活层条目里 `config:` 那一坨，原样送到这里
 */
export function apply(ctx, config) {
  const witness = config?.witness;
  if (!witness) {
    // 没给见证文件路径就没法被观测到——直接吵出来，别静默失败
    throw new Error("lab-minimal: config.witness 是必需的");
  }

  writeFileSync(
    witness,
    JSON.stringify(
      {
        marker: MARKER,
        moduleLoadedAt,
        appliedAt: new Date().toISOString(),
        config,
      },
      null,
      2,
    ),
    "utf8",
  );
}
