06-inject / activation-order

书写顺序不决定加载顺序

patch 文件里三条 insert 怎么排都不影响谁先真正 apply——谁先备齐依赖，谁先跑。

档次 ① 🔬 发现型 ✅ 满覆盖 · 2 条用例 不需要 web

这一项讲的是什么

条目（entry，配方里的一行，见 00-base/baseline-profile）会被 dsh 的 loader 一次性交给运行时去建。 一份 patch（补丁，对条目列表的一次编辑指令，整棵组合树都由 patch 叠出来）里，一个 insert 块常常一口气写好几条—— 写的时候总要挑个先后，比如先写提供服务的那条、再写要用它的那条，看着像是在暗示"先写的先跑"。这一项要讲清楚的正是这件事： 决定谁先真正开始跑的，到底是不是这几行写第几。

机制怎么工作

走一遍一批条目从"进树"到"真正 apply"的过程：①②是登记与就位这两端各自发生的事，③是框架逐条放行时用的判据，④是这条判据带来的结果。

三个教学插件的依赖链

箭头指向被依赖者。lab-registry 提供一个叫 labRegistry 的服务（service，插件之间互相提供能力的方式： 一方 ctx.provide 登记，另一方 inject 声明依赖或 ctx.get() 运行时取），自己不依赖任何人； lab-alpha 依赖它，同时自己又提供 labAlpha；lab-beta 把两个服务都声明成依赖，是链上等得最多的那个。

lab-registry 提供的账本是这一项的观测手段：谁登记一笔就立刻整份落盘，落盘顺序即真实的 apply 先后—— 拿它当时钟用，比另外拼事件流时间戳更直接。

两份 patch，顺序相反，落地顺序一样

同一条依赖链，两个 profile 各自的 cordis.patch.yml 只有 insert 里三条的书写顺序不同： 左边正着写（registry → alpha → beta），右边倒着写（beta → alpha → registry）。一步步走下去，看两边真正 apply 的先后。

读出来的是什么

①

顺序由服务就位驱动，不由行序驱动。账本文件每登记一笔就整份落盘，落盘顺序即真实 apply 先后； 正着写和倒着写两次跑下来，账本记的都是 ["lab-alpha", "lab-beta"]。 test_dependency_chain_applies_in_service_order · test_write_order_does_not_decide_load_order

②

beta 真的拿到了 alpha 提供的服务，不只是顺序凑巧对。 beta 的见证文件里 gotAlpha: true，登记时的 note 是「alpha 在这儿」—— 这是 alpha 提供的 labAlpha.greet() 的返回值，证明 beta 是等 alpha 就位后才跑的。 w-beta.json · gotRegistry / gotAlpha 均为 true

判定与证据出处在 test_activation_order.py 的模块 docstring，此页只负责让你看懂。
时序数据取自归档 results/20260817-151055/ledger.json 与 w-beta.json： lab-alpha 登记于账本计时起点后 0.7846ms，lab-beta 登记于 1.3769ms（note 为「alpha 在这儿」）。

/**
 * 提供 `labRegistry` 服务：一本「谁登记过」的账本，谁登记一笔就立刻整份落盘。
 *
 * 落盘时机就是真实的 apply 先后关系——账本内容本身就是活的调用顺序凭证，
 * 不用另外拼事件流时间戳。
 */

import { writeFileSync } from "node:fs";

const MARKER = "lab-registry-v1";

export function apply(ctx, config) {
  const ledger = config?.ledger;
  if (!ledger) throw new Error("lab-registry: config.ledger（账本落盘路径）是必需的");

  const entries = [];
  const t0 = process.hrtime.bigint();

  const dump = () =>
    writeFileSync(
      ledger,
      JSON.stringify({ marker: MARKER, providedAt: new Date().toISOString(), entries }, null, 2),
      "utf8",
    );

  const book = {
    sign(who, note) {
      entries.push({
        who,
        note: note ?? null,
        ms: Number(process.hrtime.bigint() - t0) / 1e6,
        at: new Date().toISOString(),
      });
      dump();
    },
    list() {
      return entries.slice();
    },
  };

  ctx.provide("labRegistry", book);
  dump(); // 先落一次空账本，证明提供者自己先到位
}

{
  "name": "lab-alpha",
  "version": "0.0.0",
  "private": true,
  "type": "module",
  "exports": { ".": "./index.js" }
}

/**
 * 依赖链的中段：依赖 `labRegistry`，登记自己，并再提供一个服务 `labAlpha`。
 *
 * 它同时是消费者和提供者，所以 `lab-beta` 依赖它时构成二级依赖链。
 */

import { writeFileSync } from "node:fs";

const MARKER = "lab-alpha-v1";

export const inject = ["labRegistry"];

export function apply(ctx, config) {
  const book = ctx.get("labRegistry");
  const ledgerBefore = book ? book.list() : null;

  if (book) {
    book.sign("lab-alpha", config?.note ?? null);
    ctx.provide("labAlpha", { marker: MARKER, greet: () => "alpha 在这儿" });
  }

  if (config?.witness) {
    writeFileSync(
      config.witness,
      JSON.stringify(
        {
          marker: MARKER,
          appliedAt: new Date().toISOString(),
          gotRegistry: book !== undefined && book !== null,
          ledgerBefore,
        },
        null,
        2,
      ),
      "utf8",
    );
  }
}

{
  "name": "lab-beta",
  "version": "0.0.0",
  "private": true,
  "type": "module",
  "exports": { ".": "./index.js" }
}

/**
 * 依赖链的末端：二级依赖。要两个服务——`labRegistry`（根提供）和
 * `labAlpha`（中段提供）。它必然是三个里最后 apply 的，不是因为写在最后，
 * 而是因为它等的东西最多——这正是「加载由服务可用性驱动」的直接体现。
 */

import { writeFileSync } from "node:fs";

const MARKER = "lab-beta-v1";

export const inject = ["labRegistry", "labAlpha"];

export function apply(ctx, config) {
  const book = ctx.get("labRegistry");
  const alpha = ctx.get("labAlpha");
  const ledgerBefore = book ? book.list() : null;

  if (book) book.sign("lab-beta", alpha ? alpha.greet() : "（没拿到 labAlpha）");

  if (config?.witness) {
    writeFileSync(
      config.witness,
      JSON.stringify(
        {
          marker: MARKER,
          appliedAt: new Date().toISOString(),
          gotRegistry: book !== undefined && book !== null,
          gotAlpha: alpha !== undefined && alpha !== null,
          ledgerBefore,
        },
        null,
        2,
      ),
      "utf8",
    );
  }
}
