对照 00-base/baseline-profile：那边手写的条目全落在 include 子树里； 这里补的两条却落在根组——形态不一样，这也是「判据是服务、不是条目」的另一层证据。

①

判据是服务在不在，不是条目写没写。源码在 boot() 返回之后、 watchUserPatches() 之前查 ctx.get("hmr")——undefined 才补， 跟 patch 里写没写一个叫 hmr 的条目无关。 test_neither_declared_gets_both_supplied_at_root⚠️ 待验

②

补的条目跟手写的不一样：id 随机、落在根组。ctx.loader.create() 不传 id 时按 EntryTree.ensureId() 生成随机字符串，parent 默认 null——跟 include 子树平级，不在它下面。 test_neither_declared_gets_both_supplied_at_root⚠️ 待验

③

没有开关能关掉。整段逻辑无条件执行，判据只有 ctx.get("hmr") 一个条件，源码里找不到任何可以传参禁用的分支。 仅源码引用无用例覆盖
