这一项讲的是哪个机制

这一项讲的不是 DSH 框架本身的机制，是实验台自己怎么不撞车。本仓其余每一项 实验，都要真的拉起一个 dsh 实例才能观测到东西——真的进程、真的端口、真的 home 目录 （一套 dsh 部署落地存数据的地方，完整定义见 docs/GLOSSARY.md）。

这台机器上同一时间，往往还跑着一套在用的 dsh 实例——就是 CLAUDE.md 实验纪律里反复点名、绝不能碰的那个主实例，挂在真实 home （~/.dsh）和 3080 端口上，背后接的是真实的分发线。实验怎么跑，都不能碰到 它，撞上了代价很难收场。这一项要讲清楚的，就是实验台靠什么机制，把「跑实验」和 「那套在用的实例」摆在互不相干的两个世界里，而不是靠人记住一条「别乱跑」的纪律。

机制怎么工作

下面五步，从「一个实例需要什么」讲到「实验台怎么让这几样东西每次都不撞 车」。每一步点亮右边源码树里对应的那一行，走完这五步，前面提到的隔离机制就有一条完整 链条了。

假 home 落地形态 · out/testhome/<项名>/（隔离的物理落点）
  • out/testhome/TESTHOME_ROOT —— 所有假 home 共同的根
  • └─ isolation-guarantees/本项的假 home，环境变量 DSH_HOME 就指向这里
  • ├─ profiles/<profile>/profile —— 一套具体的组合配方，本身也是一个 npm 包
  • │ └─ node_modules/junction 农场，link 供给落地在这里
  • └─ logs/实例的 stdout / stderr
  • out/testhome/.lab-lock.json会话锁文件，跟各项假 home 目录同级
实验台源码里管这件事的几个名字
  • experiments/lab/core.py
  • ├─ TESTHOME_ROOT假 home 的根，LabHome 只能建在它下面
  • ├─ LAB_PORT_RANGE3090–3099，端口分段的原料
  • ├─ FORBIDDEN_PORTS(3080, 3239, 3733)，任何情况下都不许碰
  • └─ rmtree_safe()删目录遇到 junction 或符号链接，只拆链接本身，不递归进去
  • experiments/lab/instance.py
  • └─ acquire_lock()拿不到就排队等待，只认活着的 pid
  • experiments/conftest.py
  • └─ _my_ports()按 xdist worker 把端口段切成互不重叠的几份
