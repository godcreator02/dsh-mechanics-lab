给它传配置

把「换个地方跑就要改一改」的值从代码里挪出来，写进 patch。 插件只改一行——把 apply 的第二个参数报出来。

uv run pytest experiments/step3_pass_config/ -n 0 -s · 4 个用例 · 约 15 秒

现场

四个实例，只有 patch 里那段不同

每个变体一个 profile
out/testhome/step3/profiles/
├─ plain/     正常传
├─ nested/    嵌套结构
├─ empty/     一个都不写
└─ typo/      键名拼错

每个目录里的东西跟第 2 步一样：
  package.json
  cordis.patch.yml   ← 只有这里不同
  echo.mjs
  cordis.yml
  node_modules/lab-recorder

四个变体各起一个独立实例，互不干扰——所以「不写 config」和「拼错键名」 能被干净地分开对比。

echo.mjs — 跟第 2 步只差一行
export const inject = ["labObserver"];

export function apply(ctx, config) {
  const say = ctx.labObserver.for(ctx);
  // 单独报一次类型：undefined 进 JSON 会让整个键消失，
  // 不记类型就分不清「收到 undefined」和「压根没报这个字段」
  say("我收到的 config", {
    类型: typeof config,
    内容: config ?? null,
  });
}
config 走的这条路
patch 里的 config: → 条目 → apply 的第二个参数

没有中间加工、没有 schema 校验拦一道——你写什么形状，插件就收到什么形状。

跑出来

写进去的 vs 报出来的

patch 里写的
- id: echo
  name: ./echo.mjs
  config:
    问候语: 你好
    重试次数: 3
    啰嗦: true
→
插件报出来的
{"问候语":"你好",
 "重试次数":3,
 "啰嗦":true}
嵌套也不变形
  config:
    服务器:
      主机: 127.0.0.1
      端口: 3090
    名单: [甲, 乙]
    空值: null
    小数: 3.14
→
插件报出来的
{"服务器":{"主机":"127.0.0.1",
           "端口":3090},
 "名单":["甲","乙"],
 "空值":null,
 "小数":3.14}
一个 config 都不写
- id: echo
  name: ./echo.mjs
→
插件报出来的
undefined
键名拼错了
  cofnig:
    问候语: 你好
→
插件报出来的
undefined

后两组结果完全一样，而且全程没有任何报错或警告。 patch 里多写一个没人认识的键，框架既不拦也不提醒——插件照常跑起来，只是拿不到配置。

所以插件侧要这么接
const greeting = config?.问候语 ?? "默认值";

把 config 当成「可能整个没有」来写。类型也一样：YAML 里 3 是数字、"3" 是字符串、true 是布尔、 "true" 是字符串——加不加引号是两个东西。
