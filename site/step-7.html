配置不止一处

前六步一直在改 profile 目录里那个 cordis.patch.yml。 其实 home 目录下还有一个——它对这个 home 下的每一个 profile 都生效。

uv run pytest experiments/step7_more_than_one_place/ -n 0 -s · 4 个用例 · 约 12 秒

两处

它们是拼起来的，不是二选一

profiles/你的 profile/cordis.patch.yml
# 只管这一个 profile
- insert:
    - id: 在 profile 这处
      name: ./reporter.mjs
home 根目录/cordis.patch.yml
# 管这个 home 下所有 profile
- insert:
    - id: 在 home 那处
      name: ./reporter.mjs
↓ 拼起来 ↓
树上：timer   hmr   lab-recorder   include
      在 profile 这处   在 home 那处

两条都在，各收各的 config。

不是「后面的盖掉前面的」，是两条各算各的。 只要 id 不一样，写在哪一处都只是「多一条」而已。

home 那处的作用范围

写一次，同一个 home 下每个 profile 都吃到

home 那处写了一条 → 起两个不同的 profile：

  profile twin-a 收到：{'出处': 'home 那处'}
  profile twin-b 收到：{'出处': 'home 那处'}

顺带验到一件容易想岔的事：条目写在 home 那处，但 name: ./reporter.mjs 这种相对写法仍然相对「用哪个 profile 启动」的那个目录解析—— 跟这一条写在哪一层无关。

撞车

同一个 id 两处都写，实例直接起不来

profile 这处
- insert:
    - id: both
      name: ./reporter.mjs
home 那处
- insert:
    - id: both
      name: ./reporter.mjs
启动日志（退出码 1）
Error: dsh: plugin tree failed to load:
  failed to apply loader entry include (cordis:include):
  duplicate loader entry id: both

因为两处是拼起来的，同一个 id 写两次就成了两条——挂载时查重，当场抛错。 不是后面的赢，也不是两份一起跑：谁都不算数，进程退出。

这也说明：光靠 insert 这一种写法，你没法「改」一条已经存在的条目—— 再写一遍只会撞车。真要改它，得换个写法。那正是下一步的事。
