挂上了但没执行

条目在树上、name 也找得到、文件一点毛病没有——它就是从来没跑过。 因为它在等一个永远不来的东西。

uv run pytest experiments/step9_mounted_but_never_ran/ -n 0 -s · 3 个用例 · 约 9 秒

那行 inject

从第 1 项用到现在，一直没解释

你写的每个插件开头都有这么一行，一直是「照着写」： 

export const inject = ["labObserver"];

它的意思是：我要用这个东西，没有它我就先不跑。 框架会一直等到它就位，才让你的 apply 开始执行。

那如果等的东西永远不来呢——比如多写一个根本没人提供的： 

export const inject = ["labObserver", "开锁服务"];

结果

它连开始加载都没有

这个条目走过的全部状态
PENDING → UNLOADING → DISPOSED | LOADING 从没出现过 ACTIVE 从没出现过

对照第 1 项那个正常的插件：PENDING → LOADING（这时 apply 在跑） → ACTIVE。 这次它卡在第一格，一步都没往前走。

事件流：别人都到 ACTIVE 了，它还在原地
   1.2ms  睁眼时它是 PENDING
   …timer / hmr / 观察器 / include 一路跑到 ACTIVE…
  19.4ms  include 到 ACTIVE —— 该起来的都起来了
  20.2ms  审计不过，整棵树开始拆
  21.4ms  include   ACTIVE → UNLOADING
  21.5ms  hmr       ACTIVE → UNLOADING
  22.2ms  timer     ACTIVE → UNLOADING
  22.4ms  它自己    PENDING → UNLOADING   ← 从没离开过 PENDING
  23.7ms  它自己    UNLOADING → DISPOSED
启动日志（退出码 1）
Error: dsh: plugin tree failed to load: dsh: 1 entry did not activate
  ./locked.mjs: pending (waiting for service: 开锁服务)

启动时只要有一个条目没能激活，整个实例就起不来。 跟第 4 项一样，一条出事全体停摆。但死法并不相同：那次是有条目根本没建起来、 组合压根没拼成，报错首句是「导入某个条目失败」；这次是全都建好了、只有它一直没能开始跑， 报错首句是「有 1 个条目没能激活」。看首句就能分辨该往哪查。

⚠️ 判词前半截打的是条目的 name（这里是 ./locked.mjs）， 不是 id——排错时拿 name 回 patch 文件里找。

谁在等

0-3 最小实例

本项

开锁服务

收尾那两句一字不差，退出码都是 1。

「只写 hmr 不写 timer」跟「等一个不存在的服务」是同一件事。 判词根本不区分等的人是框架自带的还是你写的，也不区分等的东西是什么—— waiting for service: X 里的 X 就是你要去补的那样东西。

对照组

不声明依赖，它就不等了

声明了 inject
export const inject = [
  "labObserver", "开锁服务"
];

export function apply(ctx) {
  // 一次都没跑到这里
}
不声明，运行时自己取
export function apply(ctx) {
  const 锁 = ctx.get("开锁服务");
  // 取不到就是 undefined，
  // 但 apply 照样跑完
}
对照组实际结果
{"跑了": true, "拿到开锁服务": false, "拿到观察器": false}
实例照常活着，它自己走到了 ACTIVE

注意最后那个 false：连观察器都没取到。 看时间线，它在 2.3 ms 就跑完了，而观察器的服务 2.2 ms 才刚出现—— 不排队就没人保证服务在不在。

这就是 inject 换来的东西：等到就位再跑。代价是万一等不到， 整个实例都起不来——所以那份名单里只写真正非有不可的。

走完了

九步之后你手上有什么

能写插件、能传配置、能临时关掉、能改别人挂上的条目、能热开发； 遇到「没跑起来」时知道分两种查：挂不上（第 4 项，报错在启动日志里， 看 module 还是 package）和挂上了没执行（这一步，看它卡在 PENDING 等谁）。

再往下是深水区：树到底长什么样、条目的完整生命周期、 以及 hmr 自己被重载时会发生什么——那些等你撞上具体问题时再来。
