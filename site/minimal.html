一个实例的下限

一个 DSH 实例能瘦到什么程度？那台仪器是上一项讲过的—— 这一页它照旧挂着，但它是装好的设备，不是这一页的内容。

uv run pytest experiments/ch0_minimal/ -n 0 -s · 2 个用例 · 约 3 秒

这一项

一个实例最少需要什么

只写 timer 和 hmr 两条。加上采集器，再算上框架自己放的树根， 一共四条——这是能瘦到的极限。

现场

假 home 里跟这次有关的全部内容
out/testhome/ch0_minimal/
├─ profiles/
│  ├─ node_modules/   252 条，dsh 自建
│  └─ minimal/
│     ├─ package.json
│     ├─ cordis.patch.yml
│     ├─ cordis.yml       dsh 写的
│     └─ node_modules/
│        └─ lab-recorder → link
├─ logs/
└─ events.jsonl        采集器写的

绿色是我们放的，灰色是 dsh 生成的。 上一层那个 252 条的 node_modules 是 dsh 维护的链接农场—— timer / hmr 写包名能被找到就靠它，不用手工装。

profiles/minimal/package.json
{
  "name": "dsh-profile-minimal",
  "private": true,
  "dsh": { "profile": { "bundles": [] } },
  "dependencies": {
    "lab-recorder": "link:…/observatory/lab-recorder"
  }
}
profiles/minimal/cordis.patch.yml — 组合就写在这
# 一个实例最少需要的两条
- insert:
    - id: timer
      name: '@deepseek-ai/cordis-plugin-timer'

    - id: hmr
      name: '@deepseek-ai/cordis-plugin-hmr'

# 仪器，独立一块 —— YAML 数组允许多个 insert 块
- insert:
    - id: lab-recorder
      name: lab-recorder
      config:
        out: "…/out/testhome/ch0_minimal/events.jsonl"
        flushMs: 100
profiles/minimal/cordis.yml — dsh 每次启动重写，别改它
# dsh profile root — an empty entry list. The tree is composed
# as patches: … Edit cordis.patch.yml, not this file.
[]

跑出来

PENDING 等依赖 LOADING 正在跑 apply ACTIVE 就绪 仪器
timer 变 ACTIVE
1.3 ms
hmr 才开始 LOADING
1.4 ms
hmr 加载耗时
8.9 ms（1.4 → 10.3）—— 整个启动几乎都花在它身上

hmr 一直在 PENDING 等着，直到 timer 变成 ACTIVE 才开始加载。 顺序不是 patch 里的书写顺序决定的，是依赖决定的。

把 timer 那两行删掉再跑一次，实例根本起不来，退出码 1，日志点名： 

@deepseek-ai/cordis-plugin-hmr: pending (waiting for service: timer)

这两条是捆绑的。至于「等一个不来的服务」到底意味着什么，第 8 项会拆开讲。
