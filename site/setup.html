先把环境备好

这套东西怎么跑、跑起来的实例住在哪、为什么它碰不到你自己那个 DSH、 跑完的东西落在哪。就这四件事。

uv run pytest experiments/ -n 0 -s · 本项没有用例 · 说明页
说明，不是实验 · 这一项没有可跑的用例，从 0-2 起才开始有

怎么跑

一条命令，你什么都不用做

不用自己建 profile、不用自己起实例、不用照着敲。实验会自己起一个隔离的实例、 自己收数据，你只看输出。 

# 首次跑之前一次就够 —— 装依赖，解释器钉死在 3.12.10
uv sync

# 跑某一项（后面每一页顶部都标着自己那条命令）
uv run pytest experiments/ch0_minimal/ -n 0 -s

# 跑全套
uv run pytest experiments/
-n 0   关掉并行 —— 各项默认同时跑，输出会交错，看不清
-s     让实验把说明打到终端 —— 页面上的数字就是这么来的

一律经 uv，不激活虚拟环境、不碰全局解释器。 机器上还得有一份能跑的 DSH——实验会自己去找它，找不到会当场说清楚。

跑在哪

一个假 home，每一项各占一个

DSH 把它的一切都放在一个叫 home 的目录里。实验从不使用你自己那个， 而是在项目的 out/ 下现造一个——每一项一个，互不相干。 

out/
├─ testhome/            假 home 都在这
│  ├─ ch0_observer/     0-2 用的这个
│  │  ├─ profiles/       实例的组合都在这
│  │  ├─ logs/           起不来的时候先看这
│  │  └─ events.jsonl    采集器写的事件流
│  └─ ch0_minimal/      0-3 用的这个
└─ results/              每次运行的归档

假 home 的名字就是那一项实验目录的名字——跑了 experiments/ch0_minimal/，就去 out/testhome/ch0_minimal/ 里翻。

每一项起手先把自己那个假 home 整个删掉重建，所以随便跑几次结果都一样； 跑完留在原地，你随时能翻进去看。

为什么碰不到你的

三条护栏，靠机制不靠自觉

home
DSH_HOME 只经子进程的环境传给实例，当前这个进程的环境一个字都不改—— 所以不存在「改完忘了改回来」那种窗口。而且它只可能指向 out/testhome/ 底下，绝不指向你自己那个 home。
端口
实验实例只用 3090–3099 这十个口。上下界都是硬的—— 再往上往下都可能有别的东西在听，越界直接拒绝启动。
删目录
清理时逐层拆链接，绝不跟着链接走。假 home 里有大量指向真实源码的 目录链接，一路跟进去删就会删到真东西。

隔离是物理的，不是靠纪律的。 你自己那个 DSH 里的会话、凭据、装好的插件，从头到尾没被读过也没被写过—— 实验实例根本不知道它存在。

跑完看哪

四样东西，后面每一页的数字都出自这里

# 实例的组合 —— 这一项到底挂了哪几条
out/testhome/<项>/profiles/<profile 名>/cordis.patch.yml

# 启动日志 —— 实例起不来，第一现场永远是这里
out/testhome/<项>/logs/<profile 名>.err.log

# 事件流 —— 采集器记下的一切，页面上的毫秒数都读自它
out/testhome/<项>/events.jsonl

# 归档 —— 这次运行的用例结果与全部输出，翻它比翻终端靠谱
out/results/<项>-<时间戳>/summary.md

整个 out/ 都是产物，删掉重跑就能再生，不用留着。

页面上的每一个数字、每一段报错、每一份文件内容，都是从上面这些文件里取的。 没有手抄，也没有转述——你跑一遍就能自己对上。
