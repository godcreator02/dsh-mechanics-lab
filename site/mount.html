把自己写的东西挂上去

0-3 那个实例里全是框架自己的东西。这一步加一个你写的插件——一个文件， 没有 package.json，没有构建，没有 npm install。

uv run pytest experiments/step2_mount_your_plugin/ -n 0 -s · 3 个用例 · 约 20 秒

现场

profile 目录里只多了一个文件

profiles/mine/
profiles/mine/
├─ package.json
├─ cordis.patch.yml
├─ hello.mjs          ← 就是它
├─ cordis.yml
└─ node_modules/
   └─ lab-recorder → link

插件就一个文件，扔进 profile 目录就行。仪器仍然走 link，因为它是个包； 你写的东西不用是包。

hello.mjs — 一个插件的全部家当
export const inject = ["labObserver"];

export function apply(ctx, config) {
  // 先告诉观察器「是我在说话」
  const say = ctx.labObserver.for(ctx);

  say("我的 apply 被调用了");
}

inject 那行照着写就行——它声明「我要用观察器」，框架保证 apply 跑之前它已经就位。第 8 项会回头拆开讲这行到底做了什么。

cordis.patch.yml — 在 0-3 的基础上多一块
# …前面 timer / hmr / lab-recorder 三条原样不变…

- insert:
    - id: hello
      name: ./hello.mjs   # 相对 profile 目录

跑出来

它真的跑了，而且能看到跑在什么时候

PENDING LOADING ACTIVE 仪器 / 插件说的话
采集器就绪
1.8 ms —— 它零依赖，所以最快
hello 开始 LOADING
1.9 ms —— 等到观察器了
hello 说话
2.4 ms
hello 变 ACTIVE
3.4 ms

说话在 2.4 ms，变 ACTIVE 在 3.4 ms —— apply 跑在「加载中」，不是「加载完之后」。 一个插件在自己的 apply 里是看不到自己 ACTIVE 的。

这条判定是白捡的：report 和 status 本来就在同一根时间轴上， 不用额外设计实验，两个数一比就出来了。这正是把观察器做成底层依赖的好处。

对照

文件在、但不写那一条呢

写了那一条
树上：timer, hmr, include,
      lab-recorder, hello

它说的话：
  "我的 apply 被调用了"
文件原样放着，只是不写
树上：timer, hmr, include,
      lab-recorder

它说的话：
  （一句都没有）

挂载只认 patch 里写没写，不会自己去扫目录。 文件躺在 profile 目录里不代表它会被加载——树上根本没有它这一条。 而少挂一个插件不是错误，实例照常活着。
