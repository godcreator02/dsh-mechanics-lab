挂不上，怎么查

同一个能跑的插件文件，只把条目那行 name 换六种写法。 六次全都起不来——但报错各不相同，认得出来就能一眼定位。

uv run pytest experiments/step5_when_it_wont_load/ -n 0 -s · 8 个用例 · 约 13 秒

先看结论

报错里那个词决定了往哪查

name 是不是 ./ 开头 —— 就这两个字符，决定了 DSH 怎么找它 
./ 开头  ────  当路径找，相对 profile 目录
           ├─ 文件在        ✓ 跑起来
           ├─ 文件不在      Cannot find module '…'
           └─ 指到的是目录  Directory import … is not supported

不带 ./  ────  当包名找，去 node_modules 里翻
           ├─ 包装进来了    ✓ 跑起来
           └─ 没这个包      Cannot find package '…'

同样是 ERR_MODULE_NOT_FOUND，说 module 的是按路径找，说 package 的是按包名找。 看到 package 就别再去核对文件在不在了——它压根没往那个方向找。

六种写法

文件一直躺在 profile 目录里，一个字没改

name: ./tool.mjs
对照组：写对了
✓ 实例起来，插件正常跑，说了它该说的话。
name: ./typo.mjs
路径拼错了，那个文件不存在
ERR_MODULE_NOT_FOUND
Cannot find module '<profile 目录>\typo.mjs'
imported from <profile 目录>\
name: ./tool
少写扩展名——tool.mjs 就在旁边
ERR_MODULE_NOT_FOUND
Cannot find module '<profile 目录>\tool'
跟上一种是同一类：按路径找，就找 ./tool 这个字面，不会替你补 .mjs。
name: ./toolbox
指到一个目录，里面有 index.mjs
ERR_UNSUPPORTED_DIR_IMPORT
Directory import '<profile 目录>\toolbox' is not supported
resolving ES modules
按路径找的时候不认目录，也不会去翻里面的 index.mjs——那是「按包名找」才有的待遇。
name: tool.mjs
只少了开头两个字符 ./
ERR_MODULE_NOT_FOUND
Cannot find package 'tool.mjs'
imported from <profile 目录>\
这种最坑：文件就在旁边躺着，报错却说找不到「包」。 因为没有 ./，它整个被当成包名拿去 node_modules 里翻了。
name: step5-not-linked
写了个包名，但那个包没装进来
ERR_MODULE_NOT_FOUND
Cannot find package 'step5-not-linked'
name: D:\…\tool.mjs
写了 Windows 盘符绝对路径
ERR_UNSUPPORTED_ESM_URL_SCHEME
Only URLs with a scheme in: file, data, and node are supported.
On Windows, absolute paths must be valid file:// URLs. Received protocol 'd:'

判词都是三段式，从外往里剥：plugin tree failed to load → failed to import loader entry tool（点名是哪个条目）→ 具体原因。 紧跟着还有一行带方括号的错误代码，认代码比认句子快。

还有一件要紧的

一条挂不上，整个实例都起不来

失败那次启动里，别的条目其实都跑完了
timer          → ACTIVE
hmr            → ACTIVE
lab-recorder   → ACTIVE
tool           连条目都没建起来

…然后全体被撤下来，进程退出，退出码 1

不是「跳过挂不上的那条、别的照跑」，是全员陪葬。 所以「别的插件都好好的」不能当成自己那条没问题的证据—— 真到那一步，实例根本就没起来。排错第一现场永远是启动日志。

顺带一提：实例是走正常卸载流程退出的，不是硬崩——所以采集器还来得及把事件刷完， 连收尾那条都写出来了。
