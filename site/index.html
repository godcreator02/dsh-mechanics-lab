为什么每个数字都能信

实验里装了一台采集器。它不是外挂的探针，是树上一个普通条目——写在同一个 patch 文件里，跟被观测的插件平级，没有任何特权。所以你在每张图里都会看到它。 

// 它订阅框架事件
ctx.on("internal/status", (fiber, oldValue) => { … });

// 也开一个口子，让插件自己说话
ctx.provide("labObserver", { for(callerCtx) { … } });

「框架说的」和「插件说的」进同一条流、共用一套时间轴—— 所以「插件说它拿到了 config」和「框架说这个条目就绪了」的先后关系， 是直接读出来的，不是推断的。

它也有能力上限：拿不到自己挂载之前的历史。采集器自己也要被加载， 在它睁眼之前发生的事没人记——这台仪器连自己的出生都没记全。 所有毫秒数都相对它睁眼那一刻，不是进程启动。详见 0-2 探查器。

⚠️ 你自己跑出来的毫秒数不会跟页面上一模一样，差个一两毫秒是正常的—— 那是真机上的调度抖动。会一模一样的是结构性的那些：条目有几个、 事件有多少条、重载触发几次、谁先谁后、退出码是几。页面上的判定全部落在后者上， 没有一条依赖某个精确的毫秒值。

跑法：uv run pytest experiments/<某一项的目录>/ -n 0 -s（每项各自可跑）
全套并行跑完约 100 秒；每项一个隔离的假 home，互不干扰。
第三到五章开工前要先扩观测手段——看「effect 清了什么」得直接读 fiber 的 effect 列表， 看「哪些条目被重挂」得有条目级 diff。
